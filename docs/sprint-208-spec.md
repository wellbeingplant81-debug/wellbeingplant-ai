## 1. 조사 결과

운영자가 베타를 시작하려면 두 가지를 알아야 한다.

```
나눠 줄 물건이 갖춰졌는가        디스크를 본다
받을 준비가 됐는가               받은 기록을 어디에 넣는가
```

지금 이 둘이 어디에 있는지 확인했다.

| 알아야 하는 것 | 지금 어디에 있는가 |
|---|---|
| 폴더에 넷이 다 있는가 | `패키지 확인` (낱장) |
| 도구가 받은 폴더 것인가 | `패키지 확인` (낱장) |
| 배경 음악이 있는가 | `배포 확인 정보`의 주의사항 |
| 받은 기록을 넣는 자리 | **`베타 현황` 한 곳뿐** |
| 지금 몇 벌을 보고 세는가 | 여러 카드에 흩어짐 |
| **언제 지은 판인가** | **아무 데도 없다** |

### 마지막 줄이 실제로 사고를 냈다

Sprint201에서 `dist/`의 exe가 2026-08-09 빌드였고, Sprint192~200이
들어 있지 않았다. 그것을 알아챈 것은 사람이 날짜를 눈으로 본 덕이지
화면이 말해 준 것이 아니다.

`app_info.build_date()`가 이미 있다. `build_info.json`을 읽어 언제
묶었는지 돌려준다. **그런데 어느 화면도 그것을 쓰지 않는다.**

### 나눠 줄 물건과 받을 준비가 갈라져 있다

Sprint207이 `패키지 확인`을 묶지 않은 이유는 "기록이 아니라 디스크를
본다"였다. 그 말은 맞다. 그런데 **베타를 시작하는 사람에게는 둘이 한
질문이다** - "지금 이걸 남에게 줘도 되는가".

## 2. 이번에 하는 것 — 카드를 늘리지 않는다

Sprint207이 방금 정한 것을 지킨다. **열셋째 단추를 만들지 않는다.**

`먼저 볼 것`으로 정해 둔 그 카드(`처음 사용자 테스트`) 안에 한 묶음을
더한다.

```
베타를 시작하기 전에
  O 나눠 줄 폴더    갖춘 것 17 · 못 갖춘 것 0 · 모르는 것 0
  ? 언제 지은 판     묶은 적이 없습니다 (개발 중)
  · 받은 기록 넣는 자리   .dataset\collected · 지금 0벌
```

전부 이미 있는 값이다.

| 줄 | 어디서 오는가 |
|---|---|
| 나눠 줄 폴더 | `beta_package_validation`의 셈 그대로 |
| 못 갖춘 줄 | 그 안에서 `ok is False`인 줄 그대로 |
| 언제 지은 판 | `app_info.build_date()` |
| 받는 자리 | `beta_dashboard`의 `collected_dirname` |
| 지금 몇 벌 | `summary["installations"]` |

### 판정하지 않는다

- **`언제 지은 판인가`는 사실이지 판정이 아니다.** "너무 오래됐다"고
  말하지 않는다 - 며칠이면 오래된 것인지 우리가 정할 일이 아니고,
  그것을 정하는 순간 새 기준이 생긴다. 날짜를 적고 사람이 본다
- 나눠 줄 폴더의 O/X/?는 `beta_package_validation`이 내린 것을 옮긴다
- 새 셈이 없다

### 경로를 통째로 적지 않는다

받는 자리는 `.dataset\collected`처럼 **내 자리 아래의 상대 이름**만
적는다. `베타 현황`이 이미 그렇게 한다. 통째로 적으면 사용자 이름이
함께 나간다(Sprint198에서 정리한 그 문제다).

## 3. 읽기는 여전히 한 번인가

`beta_package_validation`은 디스크만 본다 - 기록을 **0회** 읽는다

그 사실을 테스트가 지킨다.
