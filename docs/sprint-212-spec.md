## 2. 최신 코드가 들어갔는지 어떻게 아는가

지난 회차들은 **화면 글자**로 확인했다. 이번엔 그것으로 부족하다 -
Sprint210·211이 고친 것은 **경로를 재는 방법**이지 화면 글자가 아니다.

그래서 **동작으로** 확인한다.

```
프로그램  C:\Temp\AI영상제작소-RC212
내 자리   C:\Temp\AI영상제작소-RC212-home      <- 이름이 겹치는 이웃
```

이 배치에서 묻는다.

| API | Sprint210·211 전 | 후 |
|---|---|---|
| `beta-package-validation`의 `separated` | **X** | **O** |
| `beta-readiness`의 `data_separated` | **X** | **O** |
| 둘이 같은 답인가 | 아니오 | 예 |

파일 날짜는 거들 뿐이고, **이 셋이 최신 코드의 지문이다.**

## 3. 실제 제작 흐름 — 이번엔 끝까지 가 본다

Sprint202는 `image_prompt 없음`에서 멈췄다. Sprint203~205가 그것을
더 일찍·더 또렷하게 막게 했지만, **영상이 끝까지 나온 적은 아직 한
번도 없다.**

이번엔 막히는 것을 미리 치우고 간다.

```
1. 대본        image_prompt 를 갖춘 것으로 넣는다
2. script check  붙여넣기 자리에서 미리 본다 (Sprint205)
3. 프로젝트 생성
4. 자료 연결    images / voices 를 만들어 둔다
5. 배경 음악    inbox 에 mp3 를 넣는다        <- 이것이 없어 못 갔다
6. 제작 시작
7. 렌더 진입 → 완료
8. 결과 확인
```

다섯째는 **사용자가 할 일**이지 코드가 할 일이 아니다. README가 그
자리를 알려 준다. 시험에서는 ffmpeg로 만든 소리를 넣는다 - 남의 곡을
쓸 수 없기 때문이고, 그 사실을 보고에 적는다.

### 성공과 실패를 무엇으로 판정하는가

```
성공   final_short.mp4 가 생기고 ffprobe가 길이를 읽는다
실패   그 전에 멈춘다
```

**어느 쪽이든 고치지 않는다.** 멈추면 어디에서 무슨 말을 하며
멈췄는지 적는다. 이 회차의 목적은 통과가 아니라 확인이다.
