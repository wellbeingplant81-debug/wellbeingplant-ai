- 상태: 완료 (검증만 · 코드 변경 없음)

## 1. 어떤 환경을 만들었나

여러 회차 미뤄 둔 조건을 이번에 갖췄다.

```
1. 진짜 zip 으로 묶었다        169.2 MB
2. 새 폴더에 풀었다             C:\Temp\베타사용자\
3. PATH 에서 ffmpeg 를 뺐다     System32 만 남김
```

셋째가 핵심이다. 이 PC에는 `C:\ffmpeg\bin`이 PATH에 있어서, 지금까지
"받은 폴더의 도구를 쓴다"는 것을 **말로만** 확인해 왔다.

빼고 나서 `ffmpeg`가 안 보이는 것을 먼저 확인한 뒤 켰다.

## 2. 결과 — 받은 사람이 영상을 만들었다

                  h264 · 1080x1920 · aac · 33.03초

### 도구를 어디서 찾았는가

```
O ffmpeg              있습니다.
O ffprobe             있습니다.
O PATH에 기대지 않음   받은 폴더 안의 도구를 쓰고 있는지 봅니다
받은 폴더 판정         O 17 · X 0 · ? 0
```

**PATH에 없는데도 O다.** 켤 때 콘솔도 ffmpeg 얘기는 안 하고 배경 음악만
말한다 - 도구는 찾았고 음악은 없다는 뜻이라 정확하다.

내 자료(이미지·음성)도 **받은 폴더의 ffmpeg로** 만들었다. 그 사람에게
있는 것이 그것뿐이기 때문이다.

### 받은 사람이 처음 보는 것

```

          · 영상 제작 · 결과 확인
```

할 일을 하나만 말한다. 누를 수 없는 버튼을 띄우지 않는다.

## 3. 발견 목록

### 발견 1 — 화면이 "못 간다"는데 실제로는 갔다 (중간)

프로젝트에 자료를 이은 뒤 화면에 물었더니

```
WORKSPACE_REQUIRED — 내 자료 폴더가 필요합니다
그림과 목소리를 어디서 가져올지 아직 정하지 않았습니다.
다음 행동  내 자료 폴더 선택 · 이어갈 수 있는가  False
```

**그 상태로 제작을 눌렀더니 200으로 통과하고 영상이 나왔다.**

원인은 둘이 다른 것을 본다는 데 있다.

| | 무엇을 보는가 |
|---|---|
| `POST /api/review/{id}/library` | 프로젝트에 자료를 잇는다 |
| `onboarding_state` | `free_workspace.remembered(store)` — **설치본 전체의 "내 자료 폴더" 선택** |

라이브러리를 이어도 그 전역 선택은 안 채워진다. 그래서 화면은 계속
"폴더를 고르십시오"라고 하고, 정작 제작은 된다.

**영향**

- 화면을 믿는 사람은 **이미 이어 둔 자료를 두고 또 고르러 간다**
- `can_continue: False`가 실제로 막지는 못한다. 화면과 API가 다른 말을
  한다 - Sprint203이 없앤 그 어긋남과 같은 모양이다

**수정 필요성**: 있다. 다만 어느 쪽이 옳은지를 먼저 정해야 한다 -
라이브러리를 이으면 전역 선택도 채울 것인가, 아니면 화면이 프로젝트의
라이브러리도 볼 것인가. 둘 다 판정 흐름을 바꾸므로 이 회차에서 정하지
않는다.

### 발견 2 — 콘솔에 절대 경로 19줄 (Sprint212와 같음)

```
콘솔 80줄 중 절대 경로가 든 줄  19줄
Traceback 없음 · 사용자명 없음
```

파이프라인의 `Saved : C:\...` 와 MoviePy의 `Building video C:\...` 다.
Sprint212에서 적어 둔 것과 같고, 고치려면 pipeline·render의 print를
건드려야 한다.

### 발견 3 — 배포 크기 169 MB (전달 수단 문제)

zip이 169.2 MB다. tools(ffmpeg + ffprobe)가 190 MB라 압축해도 이만큼
남는다. 메일로 보내기 어렵다 - **전달 수단을 정해야 한다.**

코드 문제가 아니므로 고칠 것은 없다. 다만 "폴더를 통째로 주십시오"라는
README의 말이 실제로 무엇을 뜻하는지는 정해 두어야 한다.

### 발견 4 — 품질 검사가 "짧다"고 해도 만들어진다 (설계대로)

```
대본 미리 보기   needs_work — "전체가 약 30초로 너무 짧습니다"
제작 시작        200
나온 영상        33.03초
```

Sprint203이 정한 대로다 - **계약으로 막고 품질로는 안 막는다.** 다만
받은 사람은 "수정 필요"라고 적힌 대본으로 영상을 만들게 되므로, 그
표시가 무엇을 뜻하는지 오해할 여지가 있다.

## 4. 이해하기 어려울 만한 표현

| 표현 | 왜 |
|---|---|
| `내 자료 폴더` vs `라이브러리` | 같은 것을 두 이름으로 부른다. 화면은 "폴더", API는 "library" |
| `수정 필요`(품질) | 고쳐야 만들 수 있다는 뜻으로 읽히는데, 실제로는 만들어진다 |
| `기록이 1벌뿐이라 적습니다` | 운영자용 문구인데 받은 사람 화면에도 뜬다 |

## 5. 수정 필요 여부

| 발견 | 고칠 것인가 | 왜 |
|---|---|---|
| 1. 화면과 API가 어긋남 | **정해야 함** | 어느 쪽이 옳은지 결정이 먼저다 |
| 2. 콘솔 절대 경로 | 정해야 함 | pipeline·render의 print를 건드려야 한다 |
| 3. 배포 크기 | 코드 문제 아님 | 전달 수단을 정하는 일이다 |
| 4. 품질 표시 오해 | 낮음 | 설계대로 동작한다. 문구를 다듬을 여지는 있다 |

**이 회차에서는 아무것도 고치지 않았다.**
