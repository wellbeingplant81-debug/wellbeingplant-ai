# 내보내기 절차 — 바탕화면까지

Sprint209의 절차에 마지막 두 걸음을 더한다. **코드를 고쳤는데 dist가
옛것이던 문제**가 Sprint201·209·212에서 세 번 났다.

---

## 차례

```
코드 변경
   ↓
Regression            failures=0 errors=0 · 우회 없이
   ↓
Commit
   ↓
Build                 packaging/build_release.py
   ↓
dist 검증             크기 · 생성 시각 · 최신 코드 지문
   ↓
바탕화면 exe 교체      같은 이름으로 덮어쓴다
   ↓
실행 확인             콘솔 창 · 브라우저 · 첫 화면
```

**빌드를 커밋 뒤에 둔다.** 앞에 두면 커밋 직전에 고친 것이 안 들어간다.

---

## dist 검증 — 셋으로 본다

판번호(0.1.0)는 옛 판도 똑같이 말한다. 하나만 보면 속는다.

| | 무엇을 보는가 |
|---|---|
| 1. 파일 | `dist\AI영상제작소\AI영상제작소.exe` 의 크기와 수정 시각 |
| 2. 콘솔 | 켜면 첫 줄에 `… (YYYY-MM-DDTHH:MM:SS 빌드)` |
| 3. 화면 | **이번 회차에 들어간 낱말이 첫 화면에 있는가** |

셋째가 가장 확실하다. Sprint212에서는 화면 글자가 아니라 **동작**으로
확인해야 했던 회차도 있었다(경로 재는 방법만 바뀌었을 때) - 그때는
API 응답을 지문으로 쓴다.

## 바탕화면 교체

```
대상    dist\AI영상제작소\AI영상제작소.exe   (묶인 exe만)
자리    %USERPROFILE%\Desktop\AI영상제작소.exe
방법    같은 이름으로 덮어쓴다
```

- **python 파일을 바탕화면에 두지 않는다.** 받는 사람에게 주는 것은
  묶인 exe다
- 이름을 바꾸지 않는다 - 사람이 아이콘을 이름으로 찾는다
- **exe만 옮기면 tools 를 못 찾는다.** 바탕화면의 것은 "빨리 켜 보기"
  용이고, 남에게 줄 때는 폴더를 통째로 준다

## 실행 확인

| 볼 것 | |
|---|---|
| 콘솔 창 | 검은 창이 뜬다. README가 그렇게 적어 두었다 |
| 브라우저 | 1.5초 뒤 자동으로 열린다 (`OPEN_AFTER_SECONDS`) |
| 첫 화면 | 주소가 답하고 이번 회차 낱말이 보이는가 |

**창이 실제로 눈에 보이는지는 사람이 본다.** 서버가 답하는 것까지가
코드로 확인할 수 있는 범위다.
