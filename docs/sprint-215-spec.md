- 선행: Sprint214 `9a96db0`
- 기준선: regression `ran=4283 failures=0 errors=0`

## 1. 지금 화면이 어떤가

머리줄에 누를 것과 표시가 **열넷**이다.

```
판번호 · 정보 복사 · 문의 · 베타 피드백 복사 · 사용 기록
[먼저 볼 것] 처음 사용자 테스트
[낱장으로 볼 것] Beta Snapshot · Release Report 복사 · 배포 확인 정보
                · 패키지 확인 · Beta Summary · 베타 분석 · 베타 현황
문제 해결 · 사용 기록 복사 · dataset · Production Queue
```

이 중 **열은 운영자가 보는 것**이다(Sprint191~211에서 하나씩 붙었다).
받은 사람에게는 "Beta Snapshot"도 "배포 확인 정보"도 무슨 말인지 알
길이 없고, 첫 화면에서 무엇을 눌러야 하는지 고르기만 어려워진다.

본문도 마찬가지다. `새 영상 만들기` 패널 안에 Topic·Channel·Platform·
Length·Language가 먼저 오고, 무료 제작은 그 아래 단추 하나로 들어간다.
**API 키가 없는 베타 사용자가 실제로 갈 수 있는 길은 무료 제작뿐인데,
화면은 그것을 곁가지처럼 둔다.**

---

## 2. 이번에 하는 것

**기능을 건드리지 않는다. 무엇을 먼저 보여 줄지만 바꾼다.**

### 2.1 머리줄 — 사용자 것만 남긴다

| 남긴다 | 왜 |
|---|---|
| 판번호 | 문의할 때 필요하다 |
| **정보 복사** | **README가 이것을 누르라고 적고 있다** |
| 문의 + **베타 피드백 복사** | **README가 가리키는 자리다** |
| 문제 해결 | 막혔을 때 사용자가 여는 자리다 |

| 옮긴다 (숨김 영역) | |
|---|---|
| 처음 사용자 테스트 · 배포 확인 정보 · 패키지 확인 | 운영 확인 |
| Beta Snapshot · Beta Summary · 베타 분석 · 베타 현황 | 운영 기록 |
| Release Report 복사 · 사용 기록 복사 · dataset | 운영 기록 |

숨김 영역은 `운영자 확인` 단추 하나로 연다. **`고급 설정`이 이미 쓰는
그 방식**(`toggleAdvanced` · `display:none`)을 그대로 따른다 - 새
방식을 만들지 않는다.

Sprint207이 정한 `먼저 볼 것` / `낱장으로 볼 것` 묶음은 **숨김 영역
안에서 그대로 유지한다.** 그 안에서도 무엇을 먼저 볼지는 여전히
중요하다.

### 2.2 본문 — 흐름 차례대로

```
1. 주제를 적는다        Topic
2. 만든다               무료 제작을 앞으로. 나머지 설정은 접는다
3. 결과를 본다          Video Preview · 결과 확인
```

`Channel`·`Platform`·`Length`·`Language`와 Provider 고르기는
**`고급 설정` 안으로** 옮긴다. 기본값이 이미 있고, 베타 사용자가
처음에 정할 것이 아니다.

오른쪽의 Console·Quality·Thumbnail·Scene Explorer·Regeneration·
YouTube·Analytics는 **이번에 손대지 않는다.** 만드는 중과 만든 뒤에
보는 자리라 흐름을 바꾸면 영향이 커진다.

## 3. 반드시 지킬 것

### 3.1 지우지 않는다 — 옮기기만 한다

테스트가 화면 문구를 붙잡고 있다.

| 문구 | 붙잡는 테스트 |
|---|---|
| 배포 확인 정보 | 7곳 |
| 정보 복사 | 6곳 |
| Beta Snapshot | 5곳 |
| 처음 사용자 테스트 · 문제 해결 · Beta Summary | 각 4곳 |
| 먼저 볼 것 | 3곳 |
| 패키지 확인 · 낱장으로 볼 것 · 베타 피드백 복사 | 각 1곳 |

`assertIn(문구, page)` 형태라 **숨김 영역으로 옮겨도 통과한다.**
지우면 깨진다. 그러니 지우지 않는다.

### 3.2 onclick 안에 코드를 늘어놓지 않는다

머리줄이 부르는 함수가 선언돼 있는지 보는 가드가 **14개 파일**에 있다.
Sprint204에서 `onclick="if(...){...}"`로 그 14개를 한꺼번에 깨뜨렸다.
새로 만드는 단추도 이름 있는 함수 하나만 부른다.

### 3.3 판정과 API를 건드리지 않는다

- pipeline · render · provider · AI 생성 변경 없음
- 새 엔드포인트 없음 · 기존 엔드포인트 열넷 그대로
- `onboarding_state`의 상태와 문구 그대로

## 6. 판단이 필요한 것

### 6.1 운영자 화면을 어떻게 열 것인가

| | |
|---|---|
| **A. 단추 하나 (권고)** | 머리줄 끝에 `운영자 확인`. 누구나 열 수 있지만 눈에 안 띈다 |
| B. 주소로만 | `?admin=1` 같은 것. 받은 사람이 우연히 열 일이 없다 |

**A를 권한다.** 이 서버는 `127.0.0.1`에만 열려 있고 로그인이 없다 -
숨기는 목적은 보안이 아니라 **첫 화면을 단순하게 만드는 것**이다.
B는 운영자 자신이 매번 주소를 고쳐야 해서 번거롭다.

### 6.2 `Channel` 등을 정말 접을 것인가

기본값이 `wellbeing`인데, 다른 채널을 쓰는 사람에게는 한 번 더 눌러야
하는 일이 된다. 베타 사용자가 채널을 고를 일이 있는지는 우리가 아니라
**보내는 쪽이 안다.**

접지 않고 두는 선택도 가능하다. 알려 주시면 그대로 한다.
