`test_they_share_one_ruler`가 `startswith`를 통째로 막았더니 둘이
걸렸다. 확인해 보니 성격이 달랐다.

| 자리 | 판정 |
|---|---|
| `beta_readiness`의 `said.startswith("OK")` | **정당하다.** 적어 둔 테스트 결과의 첫 낱말을 본다. 가드가 과했다 |

**고쳤다.** 같은 파일의 같은 한 줄짜리 패턴이고, 자가 방금 생겼고,
안 고치면 같은 버그로 세 번째 스프린트가 필요해진다.

가드는 `startswith` 대신 **`normcase`**(경로를 손으로 조립해 글자로
재던 흔적)를 막도록 조였고, 이웃 `toolsX` 케이스를 실제로 확인하는
테스트를 넣었다.

## 1. 무엇이 어긋나는가

같은 질문을 두 자리가 서로 다른 자로 잰다.

> 내 것이 프로그램 폴더 **밖에** 있는가

```python
# beta_package_validation  (Sprint210에서 고침)
not _inside(home, program)          # commonpath - 자리로 본다

# beta_readiness           (그대로)
not home.startswith(program)        # 글자로 본다
```

이웃인데 이름이 겹치는 폴더에서 둘이 다른 답을 낸다.

```
program  C:\Temp\RC209
home     C:\Temp\RC209-home     <- 밖이다

패키지 확인   분리됨    O
배포 확인     분리 안 됨 X
```

**같은 화면에 두 답이 함께 뜬다.** `처음 사용자 테스트` 한 장 안에
`나눠 줄 폴더`(패키지 확인)와 `Readiness`(배포 확인)가 같이 있으므로,
사람은 한 장에서 서로 어긋나는 두 말을 보게 된다.

### 아무도 못 잡는다

`test_the_separation_matches_readiness`가 둘이 같은지 이미 보고 있다.
그런데 그 테스트는 이름이 겹치지 않는 임시 폴더를 쓴다 - **그래서
어긋나도 초록불이다.**

---

## 2. 두 벌을 두지 않는다

고치는 방법이 둘이다.

| | |
|---|---|
| `beta_readiness`에 같은 함수를 한 벌 더 쓴다 | 지금은 같아지지만, **이 스프린트가 생긴 이유가 두 벌이 갈라진 것**이다 |
| **한 자를 둘이 나눠 쓴다** | 갈라질 수가 없다 |

**후자로 한다.** 순수한 경로 함수 하나를 `app/utils/paths.py`로 옮기고
둘이 그것을 부른다.

`app/utils`에는 이미 `atomic_write` · `asset_cache` ·
`subtitle_utils`가 같은 성격으로 있다. 프로세스도 파일도 건드리지 않는
함수라 그 자리가 맞다.

### 범위를 조금 넘는다 - 왜 그렇게 하는가

지시의 범위는 `beta_readiness`의 비교였다. 그런데 거기에 함수를 한 벌
더 쓰면 **다음에 또 갈라진다.** Sprint210에서 한 쪽만 고쳤더니 하루
만에 이 스프린트가 필요해졌다.

그래서 `beta_package_validation`에서 함수를 꺼내 옮기고, 두 자리가 그
하나를 부르게 한다. 옮기는 것이지 새로 만드는 것이 아니다 - 로직은
Sprint210에서 이미 검증한 그대로다.

---

## 3. 뜻은 그대로 둔다

- 묻는 것: 내 것이 프로그램 폴더 밖에 있는가 — 그대로
- 줄 이름 `data_separated` · 설명 — 그대로
- O/X/? 기준 — 그대로
- `beta_readiness`의 다른 여섯 줄 — 손대지 않는다

바꾸는 것은 **재는 방법** 하나뿐이다.
