## 2. 완료라고 가정하지 않는다

이 스프린트에서 가장 쉽게 무너지는 지점이다. 빌드가 끝났다고
"최신이 들어갔다"고 말할 수 없다 — pyinstaller는 캐시를 쓰고,
spec이 무엇을 담는지는 따로 정해져 있다.

그래서 **exe 안에 Sprint192~201의 흔적이 실제로 있는지**를 확인한다.

| 무엇으로 확인하는가 | 어떻게 |
|---|---|
| 빌드 시각이 새로워졌는가 | 빌드 전/후 exe mtime 비교 |
| 새 라우트가 들어갔는가 | 켠 뒤 그 주소가 200으로 답하는가 |
| 새 화면이 들어갔는가 | 첫 화면 HTML에 새 버튼 글자가 있는가 |

셋째가 핵심이다. **`패키지 확인`(Sprint201) · `처음 사용자 테스트`
(Sprint200) · `배포 확인 정보`(Sprint199)** 는 이번 회차에 들어간
글자다. 옛 exe에는 없다.

## 4. 실행 검증을 어떻게 하는가

exe를 켜면 콘솔이 뜨고 브라우저가 열린다. 여기서 확인할 수 있는 것과
없는 것을 나눈다.

| | 확인 방법 |
|---|---|
| 서버가 뜨는가 | 주소로 HTTP 요청을 보내 답을 받는다 |
| 첫 화면이 오는가 | 그 HTML에 아는 글자가 있는가 |
| API가 답하는가 | 여섯 자리에 요청을 보낸다 |
| **브라우저 창이 실제로 보이는가** | **사람이 봐야 한다** |

넷째는 이 자리에서 확인할 수 없다. 보고에 그렇게 적는다 - 적지 않으면
"켜 봤다"로 읽힌다.

끌 때는 작업 관리 기능으로 끝낸다. 프로세스를 뒤져 죽이지 않는다.

## 5. Smoke test — 어디까지 갈 수 있는가

**끝까지 가지 못할 것을 미리 안다.** 배경 음악이 없으면 렌더가
끝나지 않는다는 것을 README가 이미 말하고 있고, 새 자리에는 음악이
없다.

그래서 목표를 "완료"로 잡지 않는다. **어디에서 멈췄고 그때 화면이
무엇을 말했는지**를 적는다. 멈춘 자리에서 다음 행동을 말해 주는가가
Sprint200이 만든 표의 값이다.

AI 키가 없으므로 대본 생성도 부르지 않는다. 무료 제작 흐름(직접 자료)
까지가 이 자리에서 갈 수 있는 범위다.
