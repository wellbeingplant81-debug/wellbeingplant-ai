## 1. 절차

### 내보내기 전

```
1. 트리가 깨끗한가            git status
   내보내는 판이 어느 커밋인가  git log --oneline -1        <- 적어 둔다

2. 전체 시험이 녹색인가       cd cloud-run
                              ./.venv/Scripts/python.exe scripts/run_tests.py
   조건: failures=0 errors=0 · PYTHONUTF8 같은 우회 없이

3. 다시 묶는다                ./.venv/Scripts/python.exe packaging/build_release.py
```

셋째를 건너뛰지 않는다. **코드를 고쳤으면 반드시 다시 묶는다.**

### 묶은 것이 지금 코드인지 — 셋으로 본다

하나만 보면 속는다. 판번호(0.1.0)는 낡은 판도 똑같이 말한다.

```
1. 파일 시각    dist/AI영상제작소/AI영상제작소.exe 의 수정 시각
2. 콘솔        켜면 첫 줄에 "… (YYYY-MM-DDTHH:MM:SS 빌드)"
3. 화면 글자    이번 회차에 들어간 낱말이 첫 화면에 있는가
```

셋째가 가장 확실하다. 지금 회차라면 이 낱말들이 있어야 한다.

```
먼저 볼 것 · 처음 사용자 테스트 · 배포 확인 정보 · 패키지 확인
베타를 시작하기 전에
```

### 새 자리에서 켜 본다

```
4. 받은 사람과 같은 자리를 만든다
   dist/AI영상제작소 폴더를 통째로 다른 곳에 복사한다
   (zip으로 묶어 풀어도 같다. 폴더를 통째로 옮기는 것이 핵심이다)

5. 켠다        AI영상제작소.exe 를 두 번 누른다
```

켤 때 창이 말하는 것을 본다.

```
판번호와 빌드 시각
주소            http://127.0.0.1:포트/studio
내 자리         %APPDATA%\AI영상제작소
배경 음악이 없으면 그 사실과 넣을 자리
```

**조용히 실패하지 않는다** - 없는 것이 있으면 켤 때 말한다.

### 화면에서 하나만 누른다

```
6. [처음 사용자 테스트]
```

Sprint207에서 정했다. 이 한 장에 `배포 확인 정보` · `Beta Snapshot` ·
`Beta Summary` · `Beta Readiness` · `Release Report`가 들어 있다.
낱장을 따로 누르면 서로 다른 순간을 보게 된다.

거기서 볼 것.

```
베타를 시작하기 전에
  나눠 줄 폴더    못 갖춘 것이 0인가
  언제 지은 판    방금 묶은 그 시각인가          <- 1절의 그 실수를 여기서 잡는다
  받은 기록 넣는 자리   .dataset\collected

여덟 걸음         지금 이 설치본이 어디까지 갔는가
주의사항          배경 음악 · 기록이 몇 벌뿐인지
```

### 배경 음악을 넣는다

```
7. %APPDATA%\AI영상제작소\music\inbox 에 mp3 한 곡
```

넣지 않으면 자료 준비와 검사까지는 되지만 **영상이 만들어지지
않는다.** 함께 배포할 수 없는 것이라 프로그램에 들어 있지 않다.

### 건넨다

```
8. 폴더를 통째로 준다 (exe만 떼면 tools를 못 찾는다)
   README.txt 를 함께 읽으시라고 말한다
```

받는 사람에게 말할 것은 README에 다 있다 - 켜는 법, 폴더를 통째로
둘 것, 음악 넣는 자리, 내 것이 쌓이는 자리, 문의처.

### 받은 뒤

```
9. 보내온 beta_usage.json 을
   %APPDATA%\AI영상제작소\.dataset\collected\ 에 넣는다
10. [처음 사용자 테스트] 를 다시 누른다
```

넣은 만큼 함께 세어진다. `설치본 N벌`이 그 수다.

## 2. 사람만 할 수 있는 것

코드로 밀어붙일 수 없는 자리다. **이 문서는 여기서 멈춘다.**

| | 왜 |
|---|---|
| 두 번 눌러 창이 뜨는가 | 화면에 창이 뜨는 것은 사람이 봐야 한다 |
| 브라우저가 열리는가 | 같음 |
| 실제로 영상이 끝까지 나오는가 | 음악을 넣고 자료를 모아 한 번 돌려야 안다 |
| 남의 PC에서도 되는가 | 그 PC에 ffmpeg가 없어야 진짜 시험이다 |

넷째가 특히 그렇다. 개발 PC에는 `C:\ffmpeg\bin`이 PATH에 있어
`도구 있음`이 O로 나온다. 받은 폴더의 것을 쓰는지는
`PATH에 기대지 않음` 줄이 말한다 - 묶인 프로그램에서 O여야 한다
(Sprint202 실측에서 개발환경 X → 묶인 프로그램 O로 뒤집혔다).

## 3. 하지 않기로 한 것

- 절차를 코드로 자동화하는 것. 빌드·복사·실행은 사람이 결정할 일이다
- 새 판정. `언제 지은 판`은 날짜를 적을 뿐 "오래됐다"고 하지 않는다
- 화면에 절차를 넣는 것. 운영자가 보는 문서이지 사용자 화면이 아니다

## 5. 절차를 밟다가 찾은 결함 — 고치지 않았다

`나눠 줄 폴더`의 X 두 줄이 **거짓 경보**다.

`beta_package_validation._user()`가 경로를 구분자 없이 문자열 앞부분만
비교한다(Sprint201에서 내가 그렇게 썼다).

```python
"separated": not home.startswith(program)
```

그래서 이름이 겹치는 이웃 폴더를 "안에 있다"고 본다.

| 경우 | 실제로 안에 있는가 | 판정 |
|---|---|---|
| `…RC209` / `…RC209-home` (이웃, 이름 겹침) | 아니오 | **X (거짓)** |
| 이웃이고 이름도 다름 | 아니오 | O |
| 진짜로 프로그램 폴더 안 | 예 | X |

### 고치지 않은 이유

이번 지시의 **"기존 판정 변경 금지"**에 걸린다. 고치려면
`startswith` 대신 경로 구분자 경계를 보아야 하고(`os.path.commonpath`
같은 것), 그것은 이 검사가 내는 답을 바꾸는 일이다.

### 베타를 막지는 않는다

기본 배치에서는 이 겹침이 생기지 않는다 - 내 자리는
`%APPDATA%\AI영상제작소`이고 받은 폴더는 사람이 푼 자리다. 이번에
드러난 것은 시험용 폴더를 `…RC209` / `…RC209-home`으로 지었기
때문이다.

방향도 안전한 쪽이다 - **안전한데 위험하다고 말할 뿐, 위험한데
안전하다고 하지는 않는다.**

절차를 한 번 밟아 본 것으로 체크리스트 자체의 결함을 찾았다. dry run이
하라는 일을 한 셈이다.
